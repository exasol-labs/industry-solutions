6 The Application: Orientation

This chapter is your map of the application window. It explains what happens between opening the address and seeing your first process map, describes every permanent element of the shell — sidebar, detail pane, title capsule, toolbar, alerts and theme — and then covers the two controls you will use most often: the view-mode menu, which switches the detail pane between the ten analysis modes, and the KPI strip, the band of figures above the chart. It is written for every user of the application, whatever their role; where a feature is restricted to power users or administrators this is stated explicitly. Later chapters describe each view mode and each sidebar section in detail.

The Launcher — one entry point

Rather than remembering a port per surface, open the Launcher at /launcher.html on the application address (for example http://127.0.0.1:8080/launcher.html, or :18080 under Docker). It is a single page, served by the application itself, that links to all four surfaces — Administration, Integration Console, Action Builder and the Work-Bench — with floating cards and arrows showing how they relate, and a Training & Documentation row that opens the built-in guides and the full PDF manual over HTTP(S). Its links adapt to wherever it is opened (native or Docker, HTTP or HTTPS), and it picks up the admin-configured sign-in background and the current version. The Launcher needs no sign-in of its own; each card leads to that surface’s own login.

Starting the application

The application always passes through the same sequence of states before the working surface appears. Understanding the sequence makes it obvious where you are if something stalls.

  1. While the application boots it shows a large spinner with the text Starting…. Nothing is interactive at this point.
  2. If the administrator has made login mandatory and you have no valid session, the Login view is shown instead of the application. The Login view also stays up during a forced two-factor enrolment, until your recovery codes have been displayed and acknowledged.
  3. The legal gate appears next. You must accept it before any part of the application UI is shown.
  4. The shell appears: sidebar on the left with the Connections section already open, detail pane on the right.
Warning Declining the legal gate signs you out and returns you to the Login view. There is no way past the gate other than accepting it; if you cannot accept the terms, contact your administrator.

Until you connect to a database, every view mode shows the same placeholder in the detail pane: the glyph ⛁, the title Not Connected and the text “Add a connection in the sidebar and tap it to connect to your Exasol database.” This is a global state, not a per-mode error — switching modes will not make it go away.

The application shell

The window is divided into two areas that never change: the sidebar on the left and the detail pane on the right.

The sidebar

The sidebar is the control surface. From top to bottom it contains the brand header (“Process Mining” over the caption “Demonstrator”, with the logo), a divider, six accordion sections, the signed-in identity footer, a divider and the theme bar.

The accordion sections are, in order: Connections, Projects, Metrics, Filters, Sampling and Configuration. Only one section is open at a time — opening a section collapses all the others. Connections is open when the application starts. The Connections and Projects headers show the number of items in parentheses, for example “Connections (3)”, whenever that number is greater than zero.

Two sections react to the active view mode:

Individual Journey
Switching to this mode opens the Filters section automatically so that the Event ID field is immediately at hand. This happens once per mode change; you may collapse the section again afterwards. The Metrics and Sampling sections are hidden entirely in this mode, because an individual journey is always drawn with a fixed Avg Time metric.
Sampling
Visible to power users and administrators only.

To reclaim horizontal space for the chart, hide the sidebar:

  1. Click ⇤ Hide sidebar in the theme bar at the very bottom of the sidebar.
  2. The sidebar disappears and a floating ▤ button (tooltip and screen-reader label “Show sidebar”) appears at the top left of the detail pane.
  3. Click ▤ to bring the sidebar back.

The detail pane

The detail pane renders the active view mode. Whatever the mode, its top edge carries the same two elements.

Title capsule (top left)
Shows the title of the selected project, falling back to “Process Map” when no project is selected. Underneath it, the name of the active view mode is shown; this second line is invisible until a project is selected.
Toolbar (top right)
Contains the ？ button (tooltip “Help”) and, when applicable, the ☰ view-switch button.

The Help panel

The ？ button opens a floating Help panel over the detail pane. The panel can also be toggled from the keyboard.

Alerts

Errors and confirmations that require your attention appear as modal alert boxes centred over a dimming scrim. An alert has a title, a message and one or two buttons — typically a primary action and a secondary Cancel. Clicking the scrim outside the box dismisses the alert.

Alerts are used consistently throughout the application. Examples you will meet early are Connection Failed (buttons Retry / Cancel, where Retry re-attempts the same connection), Failed to Load Projects and Failed to Load Project (both Retry / Cancel), No Journeys on <date> when the day slider lands on an empty day, and Note Not Synced when a note cannot be written to the database.

Theme

The theme bar at the bottom of the sidebar is labelled 🎨 Theme and offers three icon buttons: System (◐), Light (☀) and Dark (☾).

  1. Click the theme bar button you want. The change applies immediately.
  2. Leave the setting on System (the default) to follow your operating system’s light/dark preference automatically.
Note The theme is stored per user in the backend settings store as app.theme (default system). It follows you to another browser or another machine, and it is included in backups.

Switching view modes

The detail pane can display ten different analysis modes. You change between them with the toolbar’s view-switch button.

  1. Connect to a database and select a project in the sidebar. The ☰ <mode icon> button (tooltip “Switch view”) appears in the toolbar only when you are connected and a project is selected.
  2. Click ☰. A popover menu lists the available view modes; the current mode is marked with a ✓.
  3. Click a mode to switch to it. Clicking anywhere outside the menu closes it without changing the mode.

Per-mode filter memory

Each view mode keeps its own filter state — date window, included and excluded steps, meta filters and the selected transition metric. When you switch modes, the application saves the state of the mode you are leaving and restores the state of the mode you are entering. This is why the A-Chart still shows last week’s window after you have been editing filters in the B-Chart.

Two modes deviate from this rule:

Statistics
Always inherits the A-Chart’s filter state on entry. It never keeps a private filter set. The Statistics view itself displays the reminder “ⓘ Statistics use the same filters as Chart A.”
A/B Comparison
Maps onto the saved A-Chart and B-Chart states rather than holding a third state. The active (editable) side starts as A.
Note Switching to A-Chart, B-Chart, A/B Comparison, AI supported Documentation or Notes also reloads the project’s notes list, so note badges on nodes and edges are up to date in those modes.

When a project is loaded for the first time, the A-Chart loads immediately using the default date window (the last 30 days of data by default, controlled by the Default date window setting in Configuration; 0 means the full range). Every other mode is seeded with the same window plus the project’s real filter bounds, so no mode starts with an impossible range.

Tip Use this deliberately. Set the A-Chart to your reference period and the B-Chart to the period you want to question; both survive any number of trips through the other modes, and A/B Comparison then shows exactly those two states side by side.

The KPI strip

The KPI strip is the horizontal band of figures between the title capsule and the chart. It summarises the currently filtered data set in a fixed set of tiles.

Where the strip appears

The strip is shown when you are connected, a project is selected and data is present. In Individual Journey mode it appears once a journey has been loaded, and it shows a different set of tiles (see below).

The following modes render their own header instead of the shared strip: A/B Comparison (one strip per panel), Statistics, Notes, AI supported Documentation, Happy Path, Conformance Check and Simulation. Statistics and Conformance Check show the standard tiles under their own collapse handle; Notes and Simulation show tile sets of their own.

The handle: collapsing and expanding

  1. Click the chevron on the KPI handle — the narrow bar along the top edge of the strip.
  2. Collapsed, the handle shows a one-line summary in the form “filtered / total Journeys”, for example “1,234 / 10,000 Journeys”.
  3. Click the chevron again to expand the tiles.

The transitions-mode pill

At the right-hand end of the KPI handle a small pill tells you how the transitions behind the current chart were obtained. This matters for both performance and freshness. The pill is not shown in Individual Journey mode.

PillTooltipWhat it means for you
⚡ Pre-materialized “Transitions are read from the pre-materialized TRANSITIONS_RAW table.” Fastest path. Queries read a prepared table rather than deriving transitions from the raw event log.
↻ Live query “Transitions are computed live from the event log on each load.” Pre-materialisation is switched off for this connection. Every load recomputes the transitions; results are always current but slower on large logs.
⚠ Live (not built) “Pre-materialized transitions are enabled for this connection, but TRANSITIONS_RAW is not built yet — running the live query meanwhile. Rebuild it in the admin interface (Connections → Rebuild now).” An intended optimisation is missing. The chart is correct but slower than it should be.
Requires: Administrator — building or rebuilding TRANSITIONS_RAW. If you see ⚠ Live (not built), ask your administrator to run Connections → Rebuild now in the admin interface.

The standard KPI tiles

Every tile shows an icon, a label and a value. A value that cannot be determined displays as —; while a figure is still being fetched the tile shows a small spinner in place of the value.

TileIconMeaning and formatting
Total Journeys👥The unfiltered journey count of the project.
Filtered Journeys⛃The number of journeys matching the current filters.
Shortest Journey🐇Minimum journey duration. Durations are formatted by magnitude: under 60 seconds as “N s”, then “N.n min”, “N.n h”, “N.n d”.
Avg Journey⏱️Mean journey duration, same duration formatting.
Median Journey◑Median journey duration (the database MEDIAN), same formatting — the typical duration, not pulled by outliers.
Std Dev〰️Standard deviation of the journey durations, same duration formatting.
Longest Journey🐢Maximum journey duration, same duration formatting.
Graph ValueƒThe sum of (step score × visits) over all scored nodes, where visits = max(incoming, outgoing) occurrences of that step. Shown with an explicit + or − sign. The tile is hidden entirely when no step of the project carries a score.
Process Goodness◔A server-computed goodness score, shown signed with two decimals. Hidden when the server returns no value. In A/B Comparison the tile is tinted: green when this side is better than the other, red when worse, blue when the two are equal within 0.005.
Process Similarity⇄The A/B similarity, a value from 0 to 1 with two decimals. Green at 0.7 and above, red at 0.3 and below, blue in between. The tile is only present once an A/B similarity has actually been computed.
Active Sample▤The label is the side’s data source — “Original”, “Sample 1” to “Sample 3”, or “Sim-A” / “Sim-B” when a simulation is the source. The value is the journey count of that source.
Note Graph Value and Process Goodness disappear rather than showing “—” when they cannot be computed. If you expected a Graph Value and see none, no step in the project has a score; assign scores in Configuration → Steps.

Choosing and ordering the tiles

Which tiles appear, and in which order, is a per-user preference.

  1. Open the sidebar section Configuration.
  2. Expand 📊 KPIs. The list shows every tile with its icon, label and an on/off switch. All tiles are on by default.
  3. Switch a tile off to remove it from the strip.
  4. To reorder, drag a row by its ≡ handle onto another row.

The default order is: Total Journeys, Filtered Journeys, Shortest Journey, Avg Journey, Median Journey, Std Dev, Longest Journey, Graph Value, Process Goodness, Process Similarity, Active Sample. Visibility is stored as kpi.show.<id> and the order as kpi.order.

Tip The KPI settings, like all Configuration settings, are stored per user in the backend rather than in the browser. They follow you to a different browser or machine and are included in administrator backups.

The Individual-Journey KPI strip

In Individual Journey mode the standard tiles are replaced entirely — averages and totals are meaningless for a single journey. The transitions-mode pill is not shown either.

TileIconMeaning
Date📅The start date of the journey, in short date format.
Duration⏱️End minus start of the journey.
Sum of ScoresƒThe sum of the step scores across the visited steps, shown signed. Displays “—” when no scores are defined.
Steps visited / distinct⑂Two numbers, “total / distinct”. The total is the number of transitions traversed plus one; the distinct count ignores repeats, so a journey that loops shows a smaller second number.
Meta fields🏷Up to three additional tiles, one per meta attribute the project defines. The label is the project’s meta title, the value is this journey’s value. A tile only appears when both the title and a value exist.
Note Individual Journey always draws its edges with the Avg Time metric and hides the sidebar’s Metrics section, because a transition count is meaningless when each transition is traversed once.
