8 Filters, Metrics, Sampling and Configuration

This chapter is the reference for the four sidebar sections that shape what a chart shows and how it looks: Metrics (which transition figure the edges carry), Filters (which journeys are counted at all), Sampling (which data source each chart reads from) and Configuration (display settings, KPI layout, step properties and the AI prompt). Every user needs the Filters and Metrics sections; Sampling is restricted to power users and administrators. Each control is listed with its exact on-screen label, its default and — where the behaviour is easy to misread — the reason it works the way it does.

8.1 Where these sections live

All four sections are accordion panels in the sidebar, in this fixed order: Connections, Projects, Metrics, Filters, Sampling, Configuration. Only one section is open at a time — opening one collapses the others. On start-up the Connections section is open; selecting a project collapses every section so the chart gets the full height.

Two sections change with the active view mode:

  • Switching to Individual Journey hides Metrics and Sampling entirely and automatically opens Filters, so that the Event ID field is immediately at hand. The automatic opening happens once per mode change; you can collapse the section again afterwards.
  • Switching to AI supported Documentation replaces the filter controls with a notice — that view always analyses the A-Chart's filters.
Note Each view mode keeps its own filter state. Switching modes saves the state you were editing and restores the target mode's state. There are two exceptions: Statistics always inherits the A-Chart's filters, and A/B Comparison maps onto the saved A-Chart and B-Chart states, with side A active first.

8.2.1 How the metric is drawn

The chosen metric drives three visual channels at once:

Thickness
Edge width runs from 3 px to 22 px, scaled linearly against the largest value among the visible edges (for Percentage and Journey % the scale is a fixed 0–100 %). The arrowhead scales with the width.
Opacity
Alpha runs from 0.3 to 0.8 on the same linear scale, so weak transitions recede.
Colour
When Colorise edges by weight is on (see §8.5.4) the edge is tinted along the gradient configured for that metric; otherwise it is grey.

Each metric has its own colour schema, configured in the Edge Colour Schema sheet (open it by clicking the colour-scale legend on the canvas) and stored separately per metric. The built-in defaults are:

MetricDefault schemaGradient

PercentageGreen (high is good)red → green

8.2.2 Metrics and nodes

Nodes do not carry the transition metric themselves. What a node shows is its own step definition — name, colours, shape, optional description, an orange end-of-process dot, a note badge, and a score badge when the step has a score (green above zero, red below, blue at zero). Node visits, used by the Graph Value KPI, by Happy Path coverage and by the Statistics step-traffic chart, are computed as max(incoming, outgoing) occurrences — not as the sum of both, which would double-count pass-through steps.

Warning When a step group is collapsed, its edges are merged: connection counts are summed and times are weighted-averaged, and transitions inside the group disappear. Median Time, Min Time, Max Time and Std Dev cannot be reconstructed for a merged edge, so those four metrics show "—" on it. A grey hint at the bottom of the canvas repeats this while any group is collapsed.
Note In A/B Comparison, changing the metric applies it to the side you are currently editing (A or B), not to both. In Individual Journey the metric selector is hidden and the edge metric is forced to Avg Time, because a count is meaningless for a single traversal. In Conformance Check the metric chips select which metric's norms you are viewing or editing.

8.3 The Filters section

Every filter sub-section has its own collapsible header. The expansion state is remembered per user. Out of the box only Date is expanded. A sub-section that is currently narrowing the data shows a badge with its present value and a ⊗ button (tooltip "Clear <Title>") that resets just that sub-section.

The step lists carry a search field with the placeholder Search and a ⊗ button (tooltip "Clear search"). A step already present in Exclude Steps appears disabled in Include Steps and vice versa — a step can never be required and forbidden at the same time. The lists show "No project selected" when no steps are loaded and "No matches" when the search finds nothing.

The Meta sub-section appears only if the project defines at least one meta attribute title. Each field uses the placeholder All values, which is also its cleared state. Focusing a field opens the full list of distinct values (at most 50 entries are shown; the list scrolls); typing narrows it. The ▾ button (tooltip "Show values") opens and closes the list, ⊗ (tooltip "Clear") empties the field, Enter confirms the typed value and Escape closes the list. The ⊗ on the sub-section header clears all three fields at once.

8.3.2 How filters combine and when they take effect

The sub-sections narrow the journey set together: a journey must fall inside the date window, contain every step listed under Include Steps, contain none of the steps listed under Exclude Steps, and fall inside the Num Steps, Journey Time and Journey Score ranges as well as matching any meta values you have set. Clearing a sub-section removes that condition without touching the others.

Edits you make in the sidebar are staged, not live. They reach the chart when one of the following happens:

  • You press Apply.
  • You press ↺ Reset — the reset is applied immediately.
  • You click a preset, in the sidebar list or in the chart header's preset menu.
  • You use a node's context actions ✓ Require in journeys or ⊖ Exclude from journeys on the process map — these write straight into the include/exclude lists (removing the step from the opposite list) and reload the graph at once.
  • You release a handle of the journey time slider above the chart. Dragging only previews; the query fires on release.
Tip In Statistics mode the filter controls look and behave normally, but Apply recomputes the statistics view instead of the graph. Statistics always starts from the A-Chart's filters, and shows an orange "⚠ Filters changed since last load" banner if you change them afterwards.

8.3.3 The action row

Restores every filter to the project's initial values — the initial date window, empty include and exclude lists, empty meta fields and full range bounds — and reapplies immediately.
🔖 Save Preset…

8.3.4 Filter presets

A preset captures the entire current filter state — dates, include and exclude step lists, meta values and all three range bounds — under a name.

  1. Set the filters you want to keep.
  2. Press 🔖 Save Preset…. The Save Filter Preset sheet opens with the message "Saves the current filter settings as a named preset."
  3. Type a name in the Name field. Leaving it empty is allowed — the preset is then auto-named "Preset N".
  4. Press Save, or simply press Enter. Cancel discards.

Saved presets appear under the action row beneath the heading Presets, sorted alphabetically (A→Z). Four rows are visible at a time; more scroll. The same list, in the same order, is available from the preset menu button in each chart's Date & Metrics header.

  1. Click a preset name to apply it — the filters are replaced and the graph reloads immediately. The applied row is highlighted.
  2. Press ✎ (tooltip "Rename preset") to open the Rename Filter Preset sheet, which is prefilled with the current name; confirm with Rename.
  3. Press 🗑 (tooltip "Delete preset") to remove it.
Warning Preset deletion is immediate — there is no confirmation dialogue, either in the sidebar list or in the chart header's preset menu. Re-creating a deleted preset means rebuilding its filter state by hand.
Note Presets are stored in the backend settings store per user and per project. They follow you to another browser or machine and are included in backups, but they are private to you — unlike sample sets, which are shared with everyone on the same project database.

8.3.5 The Event ID filter (Individual Journey)

In Individual Journey mode the Filters section shows a single control labelled Event ID, a text field with the placeholder Enter EVENT_ID. Autocorrect, autocapitalisation and spellcheck are switched off so that identifiers are not mangled.

  1. Type at least two characters. The app fetches matching event IDs from the current project and the active A-side sample set and shows them in a dropdown while the field has focus. Typing fewer than two characters clears the suggestions.
  2. Click a suggestion — the field is filled and the journey loads at once — or finish typing the identifier yourself.
  3. Press Enter in the field, or press the Load Journey button on the right. The button is disabled while the field is blank or no project is selected.
  4. Press ⊗ (tooltip "Clear") to empty the field and the suggestion list.

Errors from loading appear in the app's standard error area, not inside the sidebar. If nothing matches, the canvas shows "🔍 Journey Not Found — No steps found for "<entered id>". Queried hash: <hash>", which gives support staff the exact value that was looked up.

Tip In the bundled demo datasets an EVENT_ID is the MD5 hash of a key such as "ORD-000001", "CRA-000001" or "FLT-000001", so the suggestions are hexadecimal strings. Type a few hex characters and pick from the list rather than trying to guess an identifier.
Note The Notes view is not governed by the sidebar filters at all; it has its own filter bar (type, importance, status, user, time, sort, grouping and page size). Notes do, however, record the filter context that was active when they were created, shown in the note editor as "Filter context: …".

8.4 The Sampling section

Requires: Power user or Administrator

Sampling lets you work on a representative subset of a large project so that charts, statistics and simulations respond quickly, and it selects which data source each chart side reads from. The section is hidden from plain users and from developers, and it is hidden in Individual Journey mode.

Warning The section carries this notice at the top: "Sample sets are stored in the project's database and are shared by everyone connected to it — unlike your personal settings and filter presets. Creating or deleting one changes it for all users of this project." Creating or deleting a sample is therefore not a private action — agree the use of the three slots with your colleagues before overwriting one.

8.4.1 Active data (A and B)

Under the heading ▤ Active data sit two dropdowns, labelled A (accent blue) and B (purple). Each chooses the data source that side's chart reads from. Both are disabled until a project is selected.

OptionShown asAvailability
Original"Original (N)" — N = total journey countalways selectable
Sample 1 / 2 / 3"Sample 1 (1,000 · Random)"disabled and labelled "Sample 1 — not created" until the set exists
Sim-A / Sim-B"Sim-A (N sim)"disabled and labelled "Sim-A — not loaded" until a simulation has been run into that slot

Your choice is stored per user (settings sampling.activeSampleSetA and sampling.activeSampleSetB, both defaulting to ORIGINAL) and the affected chart reloads at once. If a persisted choice points at a sample set that no longer exists when the project loads, that side silently falls back to Original.

Warning Choosing a simulation slot makes that side read-only. The canvas shows "<slot>: simulation data is read-only — interactive filtering, drill-down and step editing are not available.", and the node actions ✓ Require in journeys and ⊖ Exclude from journeys are hidden.

8.4.2 The three sample slots

Below the pickers are three rows, Sample 1, Sample 2 and Sample 3. Each row shows ◉ in the accent colour when the set exists and ◌ when it does not; the title is bold and accent-coloured while that set is the active source on A or B. A created set shows "N journeys" plus a method tag (icon and label, tooltip "Sampling strategy: <Method>"); an empty slot shows "Not created".

The row buttons are ＋ (tooltip "Create Sample N") on an empty slot — disabled while no project is selected or another sampling operation is running — and 🗑 (tooltip "Delete Sample N") on a filled one. While an operation runs, a spinner row shows the progress text ("Preparing…", "Writing N journeys…", or "Working…"); errors appear in red beneath the pickers.

8.4.3 Creating a sample set

  1. Press ＋ on an empty slot. The sheet Create Sample Set N (icon ▤) opens and reports "N journeys available" for the original data.
  2. Type the size in the Journeys field. The default is 1000. The value is typed freely; Create Sample stays disabled unless it is a positive whole number.
  3. Choose a Sampling Method card (see the table below). The method you used last is remembered per user and becomes your default; before that the default is Random.
  4. Press Create Sample. A spinner runs in the button; Cancel and closing the sheet are disabled while the sample is being written.
  5. On success the sheet closes and the slot fills. On failure the sheet stays open and shows "⚠ <error>" so you can adjust and retry.
MethodDescriptionUse it when
🔀 Random (initial default)Uniform random selectionYou want an unbiased miniature of the whole project.
📅 Temporal StratifiedProportional across time periodsVolume varies strongly over time and each period must stay represented.
🌿 Path DiversityCoverage across journey variantsYou care about rare routes, which uniform sampling would drop.

8.4.4 Deleting a sample set

  1. Press 🗑 on the slot. The confirmation Delete Sample Set N? appears with the message "This removes <count> sample journey rows from the database. Original data is not affected."
  2. Press Delete (red) to confirm, or Cancel to keep the set.
Note If the deleted set was the active source on side A or B, that side automatically switches back to Original and the chart reloads. The original journeys are never touched by sampling — only the generated sample rows are removed.

8.5 The Configuration section

Configuration holds display settings, the KPI strip layout, the step editor and the AI prompt. Its six collapsible sub-headers — Step Groups, KPIs, Steps, Layout, Dates and Times and AI related — are all expanded by default, and their expansion state is remembered per user. Every setting on this page is stored per user in the backend settings store, so it follows you between browsers and machines; the exception is the Steps editor, which writes shared step properties to the project database.

8.5.1 🗂 Step Groups

Show step groups
Toggle, default on. Draws a dashed tinted box with a coloured name pill around every set of steps sharing a BELONGS_TO value.
▦ Groups start
Segmented control, visible only while the toggle is on: Expanded (default) | Collapsed | Persisted. It decides whether group containers on the process map start open, start closed, or restore the state you last left them in for that project and chart mode.

  2. Use each row's switch to hide or show that tile.

The same two actions are also available directly on the KPI strip above the chart, so you rarely need to open this list. Drag any tile onto another to reorder it, and hover a tile to reveal a × in its top-right corner that hides it. The strip and this list share one order and one set of on/off flags: change either place and the other updates at once, and both persist per user. A tile you hide with its × is switched back on from this list.

Note Order and visibility apply to the KPI strip above A-Chart, B-Chart and the A/B panels — reorder or remove from either the strip or this list. Individual Journey renders its own fixed tiles (Date, Duration, Sum of Scores, Steps visited/distinct plus up to three meta tiles), which are neither reorderable nor removable and are not affected by these settings.

8.5.3 ⬭ Steps (the Step Editor)

Warning Step properties live in the project's STEPS table and are therefore shared with every user of that database. Recolouring or rescoring a step changes it for everyone, and scores feed the Graph Value KPI and the Journey Score filter.
  1. Choose a step in the Step dropdown ("— Select a step —" plus every step of the project). The editor appears only once a step is chosen; the dropdown is disabled when no project or no steps are loaded.
  2. Set Colors using the two pickers BG and FG. A live pill preview shows the step in those colours.
  3. Set the Score: tick the "set" checkbox and enter a number between −999 and 999. The number input stays disabled while the checkbox is clear; un-ticking it saves the score as unset.
  4. Pick a Shape: ▭ Stadium (default), ▢ Rounded, ⬡ Hexagon or ◯ Circle.
  5. Type a Group name (placeholder "BELONGS_TO"); existing group names are offered as autocomplete. This assigns the step to a step group.
  6. Type a Note — free multi-line text, placeholder "Shown under the step name on the map".
  7. Press Save Step. The button shows a spinner while writing; errors appear in red beside it.

Saving refreshes the score filter bounds and reloads the graph, so a changed score is reflected in the Journey Score slider and the Graph Value KPI straight away.

At the top of this Steps sub-section sits the 🗒 Show node notes toggle (default on). It controls whether each node shows its note / description under the step name on the map (truncated to 20 characters plus an ellipsis; the full text is in the hover tooltip and behind the node action ≡ Show description), along with the yellow note badges. It lives here because the note it shows is the one set in the Step editor above.

Below it, ✨ Highlight Trigger sets how long you must rest the pointer on a node before the process map spotlights that node and its incoming and outgoing transitions (dimming everything else — see §9). Choose 1 s (default), 2 s or 3 s, or Off to disable the spotlight. It applies to every process map except the Individual Journey and is stored per user.

8.5.4 ✨ Layout

A collapsible sub-section (default expanded) that groups the flow-chart rendering options: three display toggles and the flowchart font sizes.

🎨 Colorise edges by weight
Default on. Tints each transition along its metric's gradient; when off, all edges are grey and only thickness and opacity encode the metric. The same switch also appears at the top of the Edge Colour Schema sheet.

Default off. When on, a ▦ Transitions button appears in the lower-right of the A-Chart, B-Chart and both A/B-Comparison panels; it opens the underlying transition table (see §9). The button is hidden everywhere until you switch it on here.

8.5.5 🗓 Dates and Times

This category groups the time-related display settings. It currently holds one control, Default date window.

🗓 Default date window

A number input (whole numbers, minimum 0) followed by the word "days", default 30. The hint below it reads: "On load, show the last N days. 0 = full range. Applies next project load."

When a project is opened, the from-date is set to the latest event date minus N days, clamped to the project's earliest date; with N = 0 the whole range is shown. The A-Chart loads immediately with that window and every other view mode is seeded with the same window plus the project's real filter bounds.

Warning Changing this value does not reload the project you are currently working on. It takes effect the next time a project is opened. To apply it now, reselect the project — which also resets filters, A/B state, statistics and AI results.

8.5.6 ✨ AI related

This category groups the settings for the AI supported Documentation. It currently holds one control, LLM Prompt.

💬 LLM Prompt

This row pairs the label LLM Prompt with an Edit button, which is disabled until a project is selected.

  1. Press Edit. The LLM Prompt Template sheet opens with the explanation "This prompt is sent to the LLM together with the current transition table. Use it to guide the analysis style and output format."
  2. Edit the template in the large textarea.
  3. Press Save to store it, or Cancel to discard your edits.
  4. Press Reset to Default to load the built-in template back into the editor. This only fills the editor — you still have to press Save for it to take effect.

The built-in default is:

Analyze the transitions table and identify outliers, min, max, avg
values for transitions. Use project name as a title, make a decent
layout.

The template is stored per user and per project. The AI supported Documentation report prints the template it used, block-quoted, in its "Analysis Parameters" chapter, and the exact prompt that was sent is available there behind Show prompt.

8.7 What is private and what is shared

Because some of the controls in this chapter change only your own view and others change the database for everybody, it is worth knowing which is which.

ScopeCovers
Per user, cross-device (backend settings store; included in backups; private to you)Theme; all Configuration toggles and font scales; KPI order and visibility; filter sub-section expansion; active sample-set choices; default sampling method; filter presets; LLM prompt templates; happy paths; target norms; node layouts.
Shared in the project database (visible to and changed for every user of that connection)Sample sets (SAMPLE_1–3); step properties edited in the Step Editor — colours, scores, shapes, groups and step notes; notes; projects; demo data.
Session only (lost on reload or disconnect)The current connection, the selected project, unsaved filter edits and the Notes view's own filter settings.
Note Disconnecting from a database clears the whole session state — project, filters and graphs — but does not sign you out of the app, and nothing stored per user or in the project database is lost.
