4 Getting Started: Your First Session

This chapter walks you through a complete first run of Process Mining Demonstrator — Web Edition, from opening the address in your browser to reading your first process map. It is written for a new user sitting in front of the application for the first time, and it assumes nothing has been set up for you yet. Where a step needs a permission you may not have, the chapter says so and tells you who to ask. Later chapters return to each subject in depth; here the aim is simply to get a map on screen and to make sure you can name everything you see.

4.1 Before you begin

You need four things to complete a first session. If any of them is missing, the relevant section below explains how to obtain it.

What you needDetail
The application addressThe main application runs on port 8080 (HTTP) or 8443 (HTTPS). Your administrator gives you the host name — for example https://pm.example.com:8443.
A browserAny current desktop browser. Reach the server by host name, not by a bare IP address, if you intend to use passkeys.
An application accountA username and password, either a local account or a directory (LDAP / Active Directory) account. Only accounts that are enabled can sign in.
A database connectionAt least one Exasol connection assigned to your account. Without one, the Connections list is empty and no data can be loaded.
Note Your application sign-in is completely separate from the database credentials. You never type a database password into the application; those live only in the connection definition, encrypted at rest, and are never sent to the browser.

4.2 Opening the application

  1. Type the address your administrator gave you into the browser and press Return.
  2. The application shows a spinner and the word Starting… while it checks for an existing session and loads your settings.
  3. The sign-in panel appears, headed Process Mining Demonstrator.

Two banners can appear above the sign-in fields before you have typed anything:

Demo Mode — remaining time: N min
No license has been applied yet, and the installation is inside its one-time grace period. The application works normally; when the period expires the compute backend stops until a license is uploaded.
No License installed
The grace period is spent. Ask your administrator to apply a license in the admin interface under App Control → License.

If a user directory is configured, a small status light sits below the buttons: green when the directory server answered a connection test, red when it did not. The light is hidden entirely when no directory is configured.

4.3 Signing in

  1. Type your account name into Username. The field takes focus automatically.
  2. Type your password into Password.
  3. Click Sign in, or press Return. The button is disabled while the username is blank.

If two-factor authentication is required for your account, sign-in continues with a code step. If you have not yet enrolled, the application forces enrolment there and then — you cannot skip it by declining to set it up.

  1. Scan the displayed QR code with an authenticator app (Google Authenticator, 1Password, Authy or similar).
  2. Type the current 6-digit code into the confirmation field and confirm.
  3. The panel shows Two-factor is on — save your recovery codes together with a grid of one-time codes. Copy them somewhere safe now.
Warning The recovery codes are shown once and never again. Each one signs you in a single time if you lose your authenticator. If you lose both, an administrator cannot read your secret — they can only untick two-factor for your account so you can enrol afresh.

On later sign-ins you are simply asked for the current 6-digit code (or one recovery code) after your password. Once inside the application you can review the setup at any time from 🔒 Two-factor in the sidebar footer.

Signing in with a passkey

If your administrator has permitted passkeys for your account, a 🔑 Sign with Passkey button sits beside Sign in. A passkey is an alternative to your password, never a replacement — the password always keeps working, so you cannot be locked out.

  1. Sign in with your password first.
  2. Open 🔑 Passkeys in the sidebar footer, next to Sign out, and add a passkey for this device (Touch ID, Windows Hello, or a hardware security key).
  3. From then on, type your username on the sign-in panel and click 🔑 Sign with Passkey.
Note Passkeys are tied to a domain name and require a secure context. They work only when you reach the application by host name (or localhost on the same machine) over HTTPS — never by a bare IP address. If the application detects an IP address it hides the passkey controls entirely and enrolment is blocked; password sign-in works either way. A passkey sign-in also skips the two-factor code step, because it is already strong authentication.

When sign-in does not work

SymptomCause and remedy
A message says the account is lockedToo many wrong passwords. The lockout threshold defaults to 3 attempts (0 turns it off). The account carries a Locked badge in the admin Users tab; an administrator unlocks it there.
Repeated failures are refused outrightThe sign-in page throttles repeated failures from the same IP address with a short, self-clearing cooldown (HTTP 429). Wait, then try again.
Correct credentials, still refusedYour account may be disabled. Only enabled users can sign in; ask an administrator to check the Users tab. Directory accounts must also exist in the directory.
You were signed out due to inactivity.Your administrator has configured an idle timeout. Simply sign in again.
Note Your administrator can turn the login gate off altogether. The application then opens without any sign-in — but it also runs with no user identity, so every Power and Administrator capability disappears (Sampling and the advanced views are hidden and their APIs return 403), and all personal settings and filter presets fall back to one shared profile. There is no way to have both open access and the power features.

  2. Tick I have read and accept all terms stated above. Until you do, the confirm button stays disabled.

Clicking Decline signs you out and returns you to the sign-in panel. Acceptance is stored with your personal settings, so the dialog does not reappear on every visit.

4.5 Connecting to a database

After the disclaimer you see the application shell: the sidebar on the left with the Connections section already open, and an empty canvas on the right. There is no KPI strip and no date slider yet — both appear only once a chart has loaded data.

The Connections section lists only the connections assigned to you, as read-only cards sorted alphabetically by name. You cannot change a host, credentials or TLS settings here — that is the administrator's responsibility. Each card shows a database glyph (⛁), the connection Name, an optional comment line, Database: host:port, and — when a model server is attached — LLM: followed by its URL.

  1. Click a connection card. The application opens your own Exasol session against it.
  2. Watch the status dots on the right of the active card. The first dot is the database: green means "Connected", orange means "Not connected". The second dot appears only when the connection carries an LLM server: blue means "LLM reachable", orange means "LLM not reachable".
  3. On success the sidebar closes Connections and opens the Projects section for you, with the project list already loading.

Clicking the connected card again disconnects. Clicking a different card while connected disconnects first, then connects to the new one. Only one connection is active at a time, and disconnecting clears the whole session state — project, map, KPIs and filters all reset. It does not sign you out of the application.

Tip Use the ↻ button in the Connections header (tooltip "Refresh connections") after an administrator has just granted you a new connection — the list does not poll on its own.

If the list is empty you see one of two messages. Plain users see "No connections assigned to you. Ask an administrator to grant access."; users who may manage connections see "No connections yet. Use ＋ above to create one and assign users."

A failed connection raises an alert titled Connection Failed with the message and two buttons, Retry and Cancel. The message is deliberately generic — the detailed driver error goes to the server log, not to your screen.

MessageWhat it usually means
Authentication failed — check your username and password.The stored database credentials are wrong or have expired.
Connection timed out. Verify the host address, port, and network connectivity.No answer within the 15-second connect timeout.
Connection refused. No server is accepting connections at this host and port.Wrong port, or the database is not running.
Host not found. Check the hostname spelling and your DNS / network connectivity.The host name does not resolve.
TLS certificate error. Try 'Skip verification' or configure a fingerprint in the server's security settings.The certificate is not trusted. For Exasol 7.x and the Docker image the connection's minimum RSA key size must be set to 1024 bits (legacy).
This connection is not available to you.The connection is no longer assigned to your account (HTTP 403).
This connection changed during sign-in. Please reconnect.An administrator edited or deleted the connection while your session was opening.

4.6 If you have no data yet: provision a schema and generate demo data

Requires: Power user, Developer or Administrator

Regular users skip this section — ask an administrator to assign you a connection instead. With the power role (or the developer grant, or administrator rights) a ＋ button appears in the Connections header, and you can build a working environment from scratch without leaving the application: create a connection, create the schema and tables, and load a ready-made dataset.

Creating a connection

  1. Click ＋ in the Connections header (tooltip "New connection"). The New Connection sheet opens on the Database / LLM Details tab.
  2. Fill in the fields below. Only Name is mandatory to save; the database fields are needed before anything can be tested or provisioned.
  3. Click Test in the footer. The result appears beside the button: green when everything is fine, orange when one of two components failed, red when all failed. The text reads "Database OK" or "Database: error", joined by "·" with "LLM OK (N models)" or "LLM: error" when an LLM URL is set.
  4. Tick the users who should see this connection under Assigned users, then click Save.

Retype the password before using them.
Warning Saving an edit disconnects every user currently connected through that connection — they must reconnect against the new definition. Un-assigning a user drops their live session immediately, and deleting a connection drops all sessions on it first.

Creating the schema and tables

  1. On the Database / LLM Details tab, enter the target Schema name and make sure the database credentials are complete.
  2. Click Create schema & tables. The button is disabled while the Schema field is blank.
  3. On success a green line reads Created: followed by what was made — the schema plus PROJECTS, JOURNEYS, STEPS, METAS and NOTES. On failure the error appears in red, or the fallback "Could not create the schema."

Provisioning is idempotent: every statement uses IF NOT EXISTS, so re-running never disturbs existing data. If it fails part-way, the result still lists everything that was created before the failure.

Requires on the database: CREATE SCHEMA and CREATE TABLE
Warning Only your database administrator can grant those rights. The application cannot authorise you, and no amount of application-level permission substitutes for them.

Generating a demo dataset

The Demo Content tab loads a complete, realistic dataset into the connection's schema, creating the schema and tables first if they are missing. Three datasets are offered.

GroupDatasetProject IDMeta attributes 1 / 2 / 3
Retail📚 Online BookstoreBOOKSTOREPayment Method / Customer Segment / Order Value
Finance/Insurance💶 Online Credit ApplicationCREDITApplied Credit Sum / Income Class / Channel
Transportation✈️ Flight Booking & ManagementFLIGHTSJourney Type / Airline / Payment Method

Online Bookstore generates an order lifecycle — login, browse, basket, checkout, payment, fulfilment, delivery — with roughly 5 % of orders taking a returns flow and a deliberately unreliable bank-transfer path that fails about 35 % of the time per attempt and retries. Its 24 steps are grouped into Customer Interaction, Purchase Process, Payment, Fulfilment and Returns, with scores from −10 (Payment Failed, Return Initiated) to +15 (Delivered) — which means the Process Goodness KPI works out of the box.

Online Credit Application models bank and affiliate intake, an application check with a rework loop, credit assessment, and a score- and sum-driven decision with agent-review loops, ending in payment or rejection. Flight Booking & Management models a Star Alliance-style booking: 80 % new bookings (with a modify loop in search, and 50 % interline itineraries that query a partner airline's system) and 20 % manage-booking journeys. In every dataset, event times are spread randomly between 2024-01-01 08:00 and 2024-12-31 22:00.

  1. Open the Demo Content tab of the connection editor.
  2. Check the Schema field on the dataset panel you want. It is the same value as on the Details tab — editing it in any demo panel changes the connection's schema.
  3. Set Journeys. The default is 500; the minimum is 1 and the field accepts up to 20,000.
  4. Click Generate. The button reads "Generating…" with a spinner while it runs.
  5. A green line confirms the result — Created N journeys for "<title>" in <SCHEMA>.JOURNEYS — or a red one reports the error.
Note Generation replaces only that dataset's own project: its PROJECTS row, its METAS row and all of its JOURNEYS rows, including any sample sets. Other projects in the schema are untouched. STEPS rows are only added where missing, so colours, shapes and scores you have customised in the Step Editor survive a regeneration.
Note The journey count is hard-capped at 20,000 on the server and a larger request is silently clamped to exactly that. Rows are inserted in batches of 200 journeys.

Demo journeys do not use plain order numbers as case keys. Each EVENT_ID is the MD5 hash of a synthetic reference built from the dataset prefix and a 1-based, zero-padded six-digit sequence number:

Online Bookstore (BOOKSTORE):          EVENT_ID = md5("ORD-000001"), md5("ORD-000002"), …
Online Credit Application (CREDIT):    EVENT_ID = md5("CRA-000001"), …
Flight Booking & Management (FLIGHTS): EVENT_ID = md5("FLT-000001"), …

# reproduce a specific ID from a shell:
printf 'ORD-%06d' 1  | md5      # macOS  → the stored 32-char hex EVENT_ID
printf 'FLT-%06d' 42 | md5sum   # Linux
Tip You rarely need to hash anything by hand. In the Individual Journey view you can type the friendly reference — ORD-000001 — straight into the Event ID field and the application hashes it for you.

4.7 Selecting a project

With a connection live, the Projects section lists what the schema contains. Each project card shows a 📈 icon, the title and an optional description; the selected project carries a ✓.

  1. Open the Projects section if it is not already open, or press ↻ (tooltip "Reload projects") to re-read the list. The button is disabled while no database is connected.
  2. Click a project card.

Selecting a project collapses every sidebar section and does a good deal of work at once: it switches the main area to A-Chart, resets all filters, A/B state, statistics and AI results; loads the project's bootstrap data (steps, meta titles and values, date range, filter bounds and sample counts); applies your Default date window; and restores your per-user, per-project state — filter presets, target norms, happy paths and the LLM prompt template.

Note The default date window is 30 days. The map opens on the window ending at the project's latest event date and reaching back that many days, clamped to the project's earliest date. Set it to 0 in Configuration → Default date window to load the full range instead. The change applies the next time a project is opened — it does not move the slider on the current map.

If the list stays empty you see "No projects found."; before connecting it reads "Connect to a database to load projects." A failure raises the alert Failed to Load Projects (or Failed to Load Project when the selection itself fails) with Retry and Cancel.

4.8 Reading your first process map

The A-Chart is an aggregated directly-follows graph: every node is a distinct process step, and every arrow is a transition observed between two chronologically consecutive steps within the same journey. The map shows all journeys that match the current filters.

Arrows
Thickness and opacity reflect the selected transition metric relative to the largest value on the map. The label carries the value — a plain number for Count, a readable duration (4m, 1.2h, 3.5d) for the time-based metrics.
Green arrow above a node
An entry point: a step with no incoming transitions.
Orange arrow below a node
An exit point: a step with no outgoing transitions.
Score badge (top-left of a node)
The step's SCORE from the STEPS table — green for positive, red for negative, blue for zero.
Orange dot
Marks an end-of-process step.
Yellow ✎ badge
The node or edge carries at least one note.
Dashed box with a name pill
A step group: all steps sharing a BELONGS_TO value. The +/− badge collapses or expands it; a collapsed group sums connection counts and weight-averages the times.

A small pill in the chart header tells you how the transitions were computed: ↻ Live query (computed from the event log on each load), ⚡ Pre-materialized (read from a prebuilt table), or ⚠ Live (not built) (the fast path is enabled but the table is not ready, so the live query is running meanwhile). The chart footer shows the server-side query time, for example "123 ms". Chapter 12 covers the pre-materialized path.

Moving around

  1. Scroll or pinch to zoom; drag the background to pan.
  2. Double-click the background to fit the whole graph to the window. The ⤢ button does the same, and the ± buttons zoom in precise steps.
  3. Drag a node to reposition it. Positions snap to a 20 pt grid and are saved per project and per chart view. Dragging a group box moves all its members together.
  4. Press ↺ to discard your custom positions and return to the automatic layout.

Click any node to open its small action card: Require in journeys (adds the step to Include Steps and reloads), Exclude from journeys (the mirror), Show Notes (n) — where n is how many notes it already holds — and Show description, which displays the step's full DESCRIPTION when it differs from the name.

4.10 Your first filter

Filters work at journey level: a journey either qualifies in full or not at all. Nothing is applied automatically — you set the filters, then press Apply.

  1. Open the Filters section. The Date sub-section is expanded by default; all others start collapsed.
  2. Adjust From and To, or drag the two thumbs of the date slider above the map. Both thumbs respond to the arrow keys once focused.
  3. Expand Include Steps and select one or two steps. Any step already chosen for Exclude Steps is disabled here, and vice versa — a step can never be both.
  4. Click Apply. The map reloads, and Filtered Journeys in the KPI strip updates while Total Journeys stays where it was.
  5. Happy with the result? Click 🔖 Save Preset…, name it, and click Save. Leave the name blank and it is auto-named "Preset N".
  6. To start over, click ↺ Reset — it restores the project defaults and reapplies immediately.
Note A preset is a snapshot taken at the moment you save it — later filter changes do not update it. Presets are stored per user and per project, survive a change of browser, and are included in backups. Deleting one from the sidebar list happens immediately, with no confirmation dialog.
Tip Each chart view keeps its own filter settings and its own metric selection, so exploring in the B-Chart never disturbs your A-Chart.

4.11 Ending the session

Click ⏻ Sign out in the sidebar footer to end the session; this also releases your database connection. If your administrator has configured an idle timeout, the application signs you out on its own after that many idle minutes and the sign-in panel then reports "You were signed out due to inactivity." Nothing is lost: your settings, presets, layouts and notes are all stored server-side and return with you, and when you sign back in the application reconnects and reopens the project and view you were last in (see §5.6.6).
